# 排错与约束

## Framework 尚未初始化完成

错误：

```text
Framework 尚未初始化完成，不能访问 GameEntry 服务。
```

原因通常是业务在 `Awake` 中访问 `GameEntry`，早于异步初始化完成，或 Framework 已开始关闭。

处理：

- 把首轮业务初始化放到 `IGameLaunchTask.LaunchAsync`。
- 或显式 `await frameworkEntry.InitializeAsync(ct)` 后访问。
- 可选逻辑使用 `GameEntry.TryGet<T>`。
- 不用轮询 `GameEntry.Framework != null` 代替 IsReady 判断。

## Framework 功能未启用

错误：

```text
Framework 功能未启用：Network
```

强类型属性只适合确定启用的模块。检查 `FrameworkOptions.Features`，或改用：

```csharp
if (GameEntry.TryGet<INetworkSystem>(out var network))
{
    // 网络能力可用。
}
```

## 功能依赖不满足

典型错误：

```text
Framework 功能 GameData 需要先启用 Asset。
Framework 功能 UI 需要先启用 InstancePool。
```

按依赖补齐 Feature。最常见组合：

- GameData = GameData + Asset。
- InstancePool = InstancePool + Asset。
- Audio = Audio + Asset。
- Localization = Localization + Asset。
- UI = UI + InstancePool + Asset。

## Framework Scene 已存在

同一 `World` 同时初始化了两个 `FrameworkEntry`，固定名称 Scene 冲突。启动场景只能保留一个入口，并检查跨场景对象是否因 `DontDestroyOnLoad` 仍然存在。

## YooAsset 初始化失败

检查：

- `YooAssetOptions.DefaultPackageName` 是否存在。
- `PlayMode` 是否匹配当前环境。
- EditorSimulate 是否能够为目标 Package 生成模拟数据。
- Host/Fallback URL 是否在 Host 模式配置。
- 是否仅需要纯逻辑模块；若是，裁剪 Asset、ResourceUpdate、Scene，Framework 将不初始化 YooAsset。

不要在 Framework 已初始化后修改 `FrameworkOptions.YooAsset` 期待热切换；Options 已在启动时克隆。

## 资源没有释放

症状包括快照引用数持续增长、切场景后资源仍常驻、实例池无法回收。

检查所有权：

- `AssetRef<T>` / `SubAssetsRef<T>` / `RawFileRef`：`Dispose` 或 `Release`。
- `AssetPreloadToken`：`Dispose` 或 `Release`。
- `InstanceRef`：交给 `IInstancePool.Return`，或按其约定 Dispose。
- `SceneRef`：通过 SceneSystem 卸载或释放对应场景。
- Event/Network 的 `IDisposable` 订阅：持有者退出时 Dispose。
- Timer：持有者退出时 Cancel。

用 `IAssetPool.GetSnapshot`、`IInstancePool.GetSnapshot`、`IUISystem.GetSnapshot`、`INetworkSystem.GetSnapshot` 定位残留，不要只依赖 Unity Profiler 的最终现象。

## UI 没有提供 ViewKey

`OpenAsync<TUI>` 时必须满足任一条件：

- `UIOpenParams.ViewKey` 是有效的 `AssetKey.Main<GameObject>`。
- 面板重写 `GetDefaultViewKey()` 并返回有效键。

同时检查 prefab 是否为 YooAsset 可寻址资源，以及 PackageName 是否正确。

## UI 重复打开但没有新实例

默认 `UIReusePolicy.Single` 会返回已有面板并调用 `OnRefocus`。需要多个实例时使用 `UIReusePolicy.Multiple`，并确保业务能区分和关闭具体返回实例。

## Post 的事件没有立即执行

`Post` 是排队，通常在 EventBus 的 Update 中刷新；`Publish` 才是同步分发。测试或暂停状态下如果没有世界更新，可显式调用公开的 `Flush`，生产逻辑通常应让 `GameEntityRunner` 驱动。

## Timer 没有推进

确认：

- Scene 中存在并运行 `GameEntityRunner`。
- Framework 已启用 Timer。
- Timer 未 Pause/Cancel。
- `unscaled` 是否符合暂停时的预期。
- 回调目标在销毁后没有被错误保留。

## 存档 Load 返回 false

可能原因：槽位不存在、JSON 无法反序列化、类型与写入时不同、校验和不匹配或备份恢复失败。不要在失败后继续使用 out 值。需要自定义介质时实现 `ISaveStorage`，并在框架装配层替换存储实现。

## 网络 RPC 超时或断开

检查：

- Protocol 是否为请求和响应注册了不同且正确的 packet id。
- 请求实现 `INetworkRequest`，响应实现 `INetworkResponse`。
- 服务端是否原样回传请求 RpcId。
- `CallTimeoutSeconds`、心跳间隔和最大漏检次数是否适合网络环境。
- `MaxPacketSize` 与缓冲区是否足够。
- CancellationToken 是否因场景/对象销毁提前取消。

频道断开时，默认配置会终止待处理调用；应把这类失败当作连接生命周期的一部分处理。

## 异步与异常规则

- 公开异步方法返回 UniTask，调用链应尽量 await。
- `.Forget()` 只用于明确的生命周期入口，并提供异常处理器。
- CancellationToken 取消不是成功完成；上层应区分取消、网络错误和业务错误。
- 不在后台线程调用 Unity Object API；框架没有声明任意线程安全。

## 修改 Framework 前的验证

至少运行受影响模块测试：

- EditMode：EventBus、Network、ObjectPool、Procedure、Save、Timer。
- PlayMode：UISystem。

涉及初始化或依赖图时，还应在一个只含 `FrameworkEntry`/`GameLauncher` 的启动场景做冒烟验证，确认 `IsReady`、服务注册和关闭都正常。
