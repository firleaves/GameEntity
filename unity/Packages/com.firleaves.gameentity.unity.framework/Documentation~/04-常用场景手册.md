# 常用场景手册

示例只使用当前公开 API。资源 location 和包名需要替换为项目中的 YooAsset 可寻址地址。

## 场景一：安全加载并实例化临时资源

只需要普通实例时优先使用 InstancePool，它会持有底层资源引用：

```csharp
private InstanceRef _enemy;

public async UniTask SpawnEnemyAsync(Transform parent, CancellationToken ct)
{
    _enemy = await GameEntry.Instance.RentAsync(
        AssetKey.Main<GameObject>("Assets/Game/Prefabs/Enemy.prefab"),
        parent,
        new InstanceRentOptions
        {
            SetActive = true,
            Position = Vector3.zero,
            Rotation = Quaternion.identity
        },
        ct);
}

public void DespawnEnemy()
{
    if (_enemy == null)
    {
        return;
    }

    GameEntry.Instance.Return(_enemy);
    _enemy = null;
}
```

不要先用 Asset 加载 prefab，再绕过 InstancePool 自行 Instantiate，除非确实不需要池化且能管理 `AssetRef` 生命周期。

## 场景二：预加载一组战斗资源

```csharp
private AssetPreloadToken _battlePreload;

public async UniTask PreloadBattleAsync(CancellationToken ct)
{
    var group = new AssetPreloadGroup
    {
        Name = "Battle",
        Items = new[]
        {
            new AssetPreloadItem
            {
                Key = AssetKey.Main<GameObject>("Assets/Game/Prefabs/Hero.prefab")
            },
            new AssetPreloadItem
            {
                Key = AssetKey.Main<AudioClip>("Assets/Game/Audio/BattleBgm.wav")
            }
        }
    };

    _battlePreload = await GameEntry.Asset.PreloadGroupAsync(group, ct);
}

public void ReleaseBattlePreload()
{
    _battlePreload?.Dispose();
    _battlePreload = null;
}
```

预加载令牌表达“这组资源仍被需要”。不要只调用预加载而丢弃返回值。

## 场景三：UI 接收参数并管理订阅

```csharp
public sealed class CharacterPanel : UIEntity
{
    private IDisposable _changedSubscription;
    private int _characterId;

    protected override AssetKey GetDefaultViewKey()
    {
        return AssetKey.Main<GameObject>("Assets/Game/UI/CharacterPanel.prefab");
    }

    protected override UniTask OnOpenAsync(UIOpenContext context)
    {
        _characterId = (int)context.Params.UserData;
        _changedSubscription = GameEntry.Event.Subscribe<CharacterChangedEvent>(OnChanged);
        return UniTask.CompletedTask;
    }

    protected override UniTask OnCloseAsync(UICloseContext context)
    {
        _changedSubscription?.Dispose();
        _changedSubscription = null;
        return UniTask.CompletedTask;
    }

    private void OnChanged(CharacterChangedEvent evt)
    {
        if (evt.CharacterId == _characterId)
        {
            Refresh();
        }
    }
}
```

调用：

```csharp
await GameEntry.UI.OpenAsync<CharacterPanel>(
    new UIOpenParams { UserData = characterId },
    cancellationToken);
```

`UIOpenContext` 暴露打开参数中的用户数据。订阅应由面板自身释放，避免关闭后仍接收事件。

## 场景四：启动任务编排

将资源更新、数据加载、流程启动拆成不同 `IGameLaunchTask`，通过 Order 建立明确顺序：

```text
100  ResourceUpdateTask
200  LoadGameDataTask
300  StartProcedureTask
```

每个任务只负责一个阶段，并把 `CancellationToken` 传给下游。任务抛出异常时，`GameLauncher.IsLaunched` 不会变为 true，后续任务不会继续执行。

## 场景五：游戏流程状态

```csharp
public sealed class LobbyProcedure : Procedure
{
    private IDisposable _startSubscription;

    public override UniTask EnterAsync(ProcedureContext context)
    {
        context.CancellationToken.ThrowIfCancellationRequested();
        _startSubscription = GameEntry.Event.Subscribe<StartBattleEvent>(
            _ => context.ProcedureSystem.ChangeStateAsync<BattleProcedure>().Forget());
        return UniTask.CompletedTask;
    }

    public override UniTask ExitAsync(ProcedureContext context)
    {
        _startSubscription?.Dispose();
        _startSubscription = null;
        return UniTask.CompletedTask;
    }
}
```

复杂项目中应在异步切换处统一记录异常，不要让 `.Forget()` 静默吞掉失败；若事件模型允许，优先由上层异步编排器 await 状态切换。

## 场景六：可选网络模块

```csharp
if (!GameEntry.TryGet<INetworkSystem>(out var network))
{
    EnterOfflineMode();
    return;
}

network.SetDefaultProtocol(CreateProtocol());
INetworkChannel channel = network.CreateTcpChannel("game");

IDisposable listener = channel.Listen<ServerNoticePacket>(OnServerNotice);
try
{
    await channel.ConnectAsync(host, port, cancellationToken);
    await RunOnlineFlowAsync(channel, cancellationToken);
}
finally
{
    listener.Dispose();
    channel.Close();
    network.DestroyChannel("game");
}
```

离线模式属于正常分支时使用 `TryGet`，不要先访问 `GameEntry.Network` 再捕获 `FrameworkException`。

## 场景七：脏标记自动存档

```csharp
PlayerSave data = GameEntry.Save.Load<PlayerSave>(0, out var loaded)
    ? loaded
    : new PlayerSave();

GameEntry.Save.SetData(data, slot: 0);

public void AddGold(int amount)
{
    data.Gold += amount;
    GameEntry.Save.MarkDirty();
}
```

自动保存由 `SaveSystemConfig.AutoSaveInterval` 和服务 Update 驱动。关键节点（付费、关卡结算、退出）仍可主动 `Save()`，不要只依赖周期保存。

## 场景八：单元测试替换边界

业务系统依赖接口，不依赖静态门面，便于测试：

```csharp
public sealed class RewardService
{
    private readonly IEventBus _events;
    private readonly ISaveSystem _save;

    public RewardService(IEventBus events, ISaveSystem save)
    {
        _events = events;
        _save = save;
    }
}
```

组合根可从 `GameEntry` 取得接口后注入；测试直接传 Fake/Mock。只有薄的 Unity 启动层需要知道 `GameEntry`。
