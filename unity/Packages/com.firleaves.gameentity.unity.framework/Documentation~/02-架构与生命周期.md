# 架构与生命周期

## 核心角色

- `FrameworkEntry`：Unity 入口，负责初始化、关闭、运行时根节点和 `GameEntry` 注册。
- `FrameworkScene`：GameEntity 场景根节点，持有服务接口与服务注册表。
- `GameEntry`：业务侧静态门面，只在 Framework 就绪期间有效。
- `FrameworkOptions`：功能开关以及各模块配置的聚合对象；初始化时会被克隆。
- `GameLauncher`：初始化 Framework 后顺序执行启动任务。
- 服务 Entity：实现 GameEntity 的 `IAwake`、`IUpdate`、`IDestroy` 生命周期，并实现对应公开接口。

## 初始化时序

```text
FrameworkEntry.Awake
  -> 确保 GameEntityRunner 存在
  -> 创建 CancellationTokenSource
  -> InitializeAsync（默认自动执行）
      -> 克隆 FrameworkOptions
      -> 创建 Runtime Root
      -> World.Instance.AddScene("GameEntity.Unity.Framework", ...)
      -> 按 Features 初始化 YooAsset 与服务 Entity
      -> 安装 FrameworkExtensionAsset
      -> IsReady = true
      -> GameEntry.Register

GameLauncher.Start
  -> 等待 FrameworkEntry.InitializeAsync
  -> 收集 IGameLaunchTask
  -> 按 Order、类型名依次 await
  -> IsLaunched = true
```

初始化使用共享任务保证幂等：已经就绪时直接完成；正在初始化时，所有调用方等待同一个初始化结果。失败时会销毁已创建 Scene、清空引用并向所有等待者传播同一个异常。

## 服务依赖

模块依赖由 `FrameworkScene.InitializeAsync` 强制检查：

```text
Asset ─┬─> GameData
       ├─> InstancePool ─> UI
       ├─> Audio
       └─> Localization

YooAssetBootstrap ─┬─> Asset
                   ├─> ResourceUpdate
                   └─> Scene

Audio（可为空） ─> GameSettings
```

关键边界：

- `GameData`、`InstancePool`、`Audio`、`Localization` 启用时必须同时启用 Asset，否则初始化抛出 `FrameworkException`。
- UI 使用内置 `UGUIAdapter`，固定依赖 InstancePool，因此还需要同时启用 Asset。
- ResourceUpdate 与 Scene 不依赖 `IAssetPool`，但共享 YooAsset 初始化器。
- GameSettings 可在 Audio 未启用时创建，但音量设置不会同步到音频服务。

## 服务访问策略

`FrameworkScene` 使用接口类型作为服务表键：

```csharp
if (framework.Scene.TryGetService<IMyService>(out var service))
{
    // 使用扩展服务。
}

IMyService required = framework.Scene.GetRequiredService<IMyService>();
```

业务代码通常应使用 `GameEntry.TryGet<T>`，便于从任意系统访问。需要显式依赖、可测试性或避免全局状态时，把接口通过 Awake 参数、构造上下文或方法参数传入业务对象。

## 更新驱动

`GameEntityRunner` 分别驱动固定 Model 更新和普通帧更新。实现 `IFixedUpdate` 的 Model 服务由 `FixedUpdatesPerSecond` 控制，默认 30Hz；实现 `IUpdate` 的服务每个 Unity 帧收到 `Time.deltaTime`，例如：

- Asset 与 InstancePool：过期扫描和自动释放。
- Audio：播放状态维护。
- Timer：推进 scaled/unscaled 计时器。
- Event：刷新 `Post` 队列。
- Save：自动保存倒计时。
- Procedure：更新当前状态。
- Network：收包、超时与心跳处理。

因此不要在业务侧重复手动调用服务 Entity 的 `Update`；测试中的手动调用只用于隔离验证。

## 关闭时序

`ShutdownAsync` 先让 `GameEntry` 失效，再逆向销毁服务、关闭 YooAsset，最后由 `FrameworkEntry` 销毁 Runtime Root。主动关闭后需要把任何缓存的服务引用视为失效。

资源句柄的业务所有权不会因为静态入口注销而自动变得安全：仍应在所属对象的 `OnDestroy`、`finally` 或 `using` 中释放。

## 扩展服务

框架扩展通过 ScriptableObject 安装：

```csharp
using GameEntity.Unity.Framework;
using UnityEngine;

public interface ICombatClock
{
    float TimeScale { get; set; }
}

[CreateAssetMenu(menuName = "Game/Framework/Combat Clock")]
public sealed class CombatClockExtension : FrameworkExtensionAsset
{
    protected override void Install(FrameworkExtensionContext context)
    {
        var service = new CombatClock();
        context.SetService<ICombatClock>(service);
    }

    private sealed class CombatClock : ICombatClock
    {
        public float TimeScale { get; set; } = 1f;
    }
}
```

`FrameworkExtensionContext` 提供当前 Scene、克隆后的 Options、Framework Root，以及 `SetService`、`TryGetService`、`GetRequiredService`、`CreateChildRoot`。扩展安装发生在所有内置服务之后，适合依赖内置接口。

注意：普通 C# 服务不会自动收到 GameEntity 的 `IUpdate`/`IDestroy`。需要更新生命周期时，应将 Entity 添加到 `context.Scene` 下并注册其接口；非 Entity 服务若实现 `IDisposable`，Framework 关闭时会按对象引用去重释放。同一接口只能注册一次，重复注册会抛出 `FrameworkException`，不能静默替换内置服务。

## 设计约束

- Framework Scene 名固定为 `GameEntity.Unity.Framework`，同一 World 中不能同时存在两个已初始化入口。
- `FrameworkOptions` 初始化时被克隆，初始化后再修改原对象不会动态重配服务。
- `GameEntry` 是当前单实例门面，不支持多 Framework 并行。
- Unity GameObject 是运行时承载和调试投影；GameEntity Scene/Entity 才是业务生命周期真源。
- 服务公开接口属于稳定调用面；实现类的字段、更新顺序和 internal 方法不应成为业务依赖。
